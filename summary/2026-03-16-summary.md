### 二、薄弱环节复习

#### 复习题 1：BFC 触发条件

**题目：** 判断哪些元素会触发 BFC

```css
.box1 { position: relative; }      /* ❌ 不会 */
.box2 { position: absolute; }      /* ✅ 会 */
.box3 { overflow: hidden; }        /* ✅ 会 */
.box4 { transform: rotate(45deg); }/* ❌ 不会（创建层叠上下文） */
.box5 { display: flex; }           /* ✅ 会 */
.box6 { position: fixed; }         /* ✅ 会 */
```

**用户回答：** 2, 3, 5, 6 会触发 BFC

**评分：** 🟢 **A**（完全正确！）

**核心结论：**
- `transform` 创建的是**层叠上下文**，不是 BFC
- `position: relative` 不会触发 BFC
- `position: absolute/fixed` 会触发 BFC

#### 复习题 2：will-change 使用场景

**题目：** 分析 3 个场景是否适合使用 will-change

| 场景 | 用户回答 | 正确答案 | 评分 |
|------|----------|----------|------|
| A: 侧边导航栏（1 个元素，频繁交互） | ✅ 适合 | ✅ 适合 | ✅ |
| B: 2000 个小图标（hover 放大） | ✅ 适合 | ❌ **不适合**（内存爆炸） | ❌ |
| C: 轮播图 Banner（持续动画） | ✅ 适合 | ✅ 适合 | ✅ |

**用户回答：** A、B、C 都适合，因为可以让动画更平滑

**评分：** 🟡 **B-**（没有考虑内存成本）

**核心结论：**

```
will-change 使用决策树：

1. 元素数量多吗？（> 100 个）
   ├─ 是 → ❌ 不要用，内存爆炸（每层约 1-4MB）
   └─ 否 → 继续判断

2. 动画频繁吗？（持续动画 or 高频交互）
   ├─ 是 → ✅ 加上 will-change
   └─ 否 → 只用 transform 即可

3. 对性能要求高吗？（60fps 刚需）
   ├─ 是 → ✅ 加上 will-change
   └─ 否 → 可以不用
```

**错误用法示例：**
```css
/* ❌ 2000 个元素 = 2-8GB 内存 */
.icon {
  will-change: transform;
}
```

**正确用法示例：**
```css
/* ✅ 关键元素 + 频繁动画 */
.carousel {
  will-change: transform;
}

/* ✅ 用户高频交互 */
.sidebar-nav {
  will-change: transform;
}
```

## 💡 关键收获

### 1. 微前端核心价值
> 技术栈无关、独立开发、独立部署、增量升级

### 2. BFC vs 层叠上下文（重要区分）
| 概念 | 作用 | 触发条件 |
|------|------|----------|
| BFC | 解决布局问题（浮动、margin 重叠） | overflow:hidden, position:absolute/fixed, display:flex/grid, float |
| 层叠上下文 | 控制 z 轴层级 | position+z-index, transform, opacity, will-change |

### 3. will-change 使用原则
> 频繁动画用 will-change，偶尔动画只用 transform，大量元素（>100）不要滥用！
